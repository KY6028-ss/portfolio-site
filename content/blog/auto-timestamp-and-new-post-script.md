このサイトは Markdown ファイルを push するだけで記事が公開される仕組みなのですが、公開日時を frontmatter の `publishedAt` に手で書く必要がありました。書き忘れると下書き扱いのまま公開されない仕様なので、地味にハマりポイントでもありました。

そこで今回、時刻まわりを少し整備しました。

## 記事作成コマンドを追加した

`npm run new:blog -- "タイトル"` と打つと、その瞬間の時刻が `publishedAt` に入った雛形が `content/` に作られるようにしました。お知らせ用・実績用のコマンドもあります。

この記事自体も、さっそくそのコマンドで作っています。frontmatter を手で書かなくてよくなったので、「書く → push する」の気軽さがまた少し上がりました。

## ヘッダーに最終更新時刻を出した

サイトのヘッダーに「最終更新: YYYY-MM-DD HH:MM」と出るようにしました。ブログ・お知らせ・実績すべての中で一番新しい公開時刻を、ビルド時に拾って表示しています。

全ページ静的生成（SSG）なので、この時刻は記事を push して再デプロイされるたびに自動で更新されます。DB もサーバー処理もなしで「サイトがいつ動いたか」が見えるようになったのは、静的サイトにしてはちょっと便利かなと思っています。

## SSG での「アップロード時刻」の扱い

作っていて考えたことのメモです。静的サイトには「アップロードされた瞬間」を知っているサーバーがいないので、時刻はどこかに記録しておく必要があります。

- git のコミット時刻をビルド時に拾う案もあったのですが、Vercel は shallow clone するので古いファイルの履歴が取れない可能性があり、見送りました
- 結局「作成コマンドが frontmatter に時刻を書き込む」のが一番素直で確実でした。既存の公開判定の仕組み（`publishedAt` が現在時刻以下なら公開）もそのまま使えます

ちなみに時刻の整形は、外部ライブラリを入れずに `Intl.DateTimeFormat` のタイムゾーン指定で JST 固定にしています。`sv-SE` ロケールを指定すると `YYYY-MM-DD HH:MM:SS` 形式がそのまま返ってくるという小ネタも今回知りました。
