## 標準SQLと、SQLの3分類（DDL / DML / DCL）

まず言葉の整理からでした。

**標準SQL** というのは、PostgreSQL や MySQL など DBMS（データベースを動かすソフト）ごとに微妙な方言があるなかで、「共通仕様としてこう書きましょう」と決められた SQL のことでした。方言に振り回されないためにも、まずは標準の書き方を覚えるのが良さそうです。

そして SQL の命令は、役割で大きく3種類に分かれるとのこと。

- **DDL（データ定義言語）** … `CREATE` / `DROP` / `ALTER` など。データを入れる「テーブル」そのものを作ったり変えたりする系
- **DML（データ操作言語）** … `SELECT` / `INSERT` / `UPDATE` / `DELETE` など。テーブルの中の「データ」を操作する系
- **DCL（データ制御言語）** … `COMMIT` / `ROLLBACK` / `GRANT` / `REVOKE` など。変更を確定させたり、権限を制御したりする系

第1章はほぼ DDL の話でした。ここでいったん「テーブル」というのは、データを行と列で持っておく入れ物なんだな、というイメージがつかめました。

## データベースとテーブルを作る

最初は入れ物づくりから。データベースを作る `CREATE DATABASE`。

```sql
-- CREATE DATABASE データベースの作成
CREATE DATABASE <データベース名>;
```

続いてテーブルを作る `CREATE TABLE`。基本の構文はこんな形でした。

```sql
-- CREATE TABLE テーブルの作成
CREATE TABLE <テーブル名>
    (<列名> <データ型> <制約>,
    ...
    PRIMARY KEY (<主キーにする列名>));
```

※ 書籍には題材となるサンプルデータ（テーブル定義と中身の行データ）が付随していて、実際はそれを写しながら手を動かしました。この記事では要点だけ残したいので、具体名は伏せて構文の形で書き起こしています。

`CREATE` は名前のとおり **「作成」** を意味する命令でした。ここで、
- 列ごとに `CHAR` / `VARCHAR` / `INTEGER` / `DATE` みたいに**データ型**を決めること
- 列に**制約**（`NOT NULL` や `PRIMARY KEY` など）を付けられること

あたりを触りました。「テーブル（入れ物）の設計図を先に書くんだな」という感覚です。

### NOT NULL制約と主キー（PRIMARY KEY）制約

テーブル作成時に、制約（＝守らせたいルールのようなもの）が2つ出てきました。

- **NOT NULL制約** … その列に「空っぽ（`NULL`）」を許さない、という縛り。付けておくと、値の入っていない行を登録できなくなります。必須のデータとかの「ここは絶対に埋めておいてほしい」という列に付けるイメージです。
- **主キー（PRIMARY KEY）制約** … その値さえ見れば**どの行か1つに特定できる**列（の組み合わせ）を決める縛り。同じ値が2つ存在できず（重複禁止）、かつ空にもできない（自動的に NOT NULL 扱い）ので、「行を見分けるための一意の番号」という役割ですね。

主キーは「重複しない＋空にできない」の2つがセットになっているのを忘れないようにしなきゃですね。
というか、値が重複していても空っぽでも、その1行を特定できなくなるわけで、そう考えるとこの仕様は当然だなと納得しました。（多分この理解で合ってるよね？）
逆に NOT NULL は「空を許さない」だけで、重複自体は許す、という違いも整理できました。必須の情報のときとかに使う感じっぽいぞ！

## テーブル定義を変える・消す

作ったあとに列を足したり、テーブルごと消したり。

`ALTER TABLE` はテーブルの定義を後から変える命令で、**ALTER＝テーブル定義の変更**という理解をしました。

```sql
-- ALTER TABLE テーブル定義の変更
-- テーブルに列を追加する
ALTER TABLE <テーブル名> ADD COLUMN <列名> <データ型>;
-- テーブルの列を削除する
ALTER TABLE <テーブル名> DROP COLUMN <列名>;
```

そしてテーブルそのものを消すのが `DROP TABLE`。**DROP＝削除**です。

```sql
-- DROP TABLE テーブルの削除
DROP TABLE <テーブル名>;
```

`ALTER ... DROP COLUMN`（列を消す）と `DROP TABLE`（テーブルを消す）で、同じ「DROP」でも消す対象が違うのがちょっと紛らわしかったです。

## データを入れる（トランザクション）

入れ物ができたので、中身のデータを入れる `INSERT`。※ DML（データ操作言語）です。

```sql
BEGIN TRANSACTION;
INSERT INTO <テーブル名> VALUES (<値1>, <値2>, ...);
COMMIT;
```

`INSERT` を `BEGIN TRANSACTION;` 〜 `COMMIT;` で囲んでいます。ここで出てくる「トランザクション」や `COMMIT` については、書籍でも「あとの章で詳しく説明する」という扱いだったので、今日のところはまだちゃんと理解できていません。先の章で改めて向き合います。

## 練習問題（第1章）

章末の練習問題は、あるテーブルを題材に、今日覚えた CREATE / ALTER / DROP を自分でやってみる内容でした（ここも書籍のサンプルデータを使った問題です）。

```sql
-- 1_1: テーブルの作成
CREATE TABLE <テーブル名>
    (<列名> <データ型> <制約>,
    ...
    PRIMARY KEY (<主キーにする列名>));

-- 1_2: 列の追加
ALTER TABLE <テーブル名> ADD COLUMN <列名> <データ型> <制約>;

-- 1_3: テーブルの削除
DROP TABLE <テーブル名>;
```

一度削除したテーブルを復元させるコマンドを探したのですが、**DROP したテーブルを元に戻すコマンドは無い**みたいでした。
実際の運用ではバックアップとかを取っとく必要があるのかなと素人ながら考えました。
「消したら戻せない」というのは、なかなか怖いですね...業務では気をつけなければ...

## 今日のまとめ

第1章を終えて、

- `CREATE`（作成）/ `ALTER`（変更）/ `DROP`（削除）というコマンドの意味
- 標準SQLと、DDL / DML / DCL という命令の分類

このあたりがつかめました。まだ「作って・変えて・消す」の入り口だけですが、とりあえずSQLの全体観を掴めた感じがしました。
